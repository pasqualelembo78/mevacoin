# THE BLOCKER: CLSAG VERIFICATION FAILURE (NOW FIXED)
===========================================================================

**SYMPTOM**: ALL non-RCT premine spend transactions failed with "invalid input" at daemon.
Daemon log: `verRctCLSAGSimple failed for input 0` → `final_c != sig.c1`.

**AFFECTS**: ALL wallets and ALL ring sizes identically.

## Root Cause: `inSk.mask` Blinding Factor Mismatch for Non-RCT Outputs

**`rct::zeroCommit(amount)` returns `1*G + amount*H` (blinding factor = scalar 1), but the wallet
set `src.mask = 0` (scalar 0) for non-RCT outputs.** This 18-line latent bug, inherited from
Monero, was never triggered because Monero migrated all non-RCT outputs to RingCT before CLSAG
was activated.

### The Math

For a non-RCT output with ring_size=1:
```
pubs[l].mask = zeroCommit(amount) = 1*G + amount*H   (blinding factor = 1)
inSk.mask   = 0                                        (blinding factor = 0)
C_offset    = a*G + amount*H                            (pseudoOut)
z           = inSk.mask - a_pseudo = 0 - a = -a

C_precomp   = pubs[l].mask - C_offset
            = (1*G + amount*H) - (a*G + amount*H)
            = (1-a)*G                                    (DL = 1-a)
```

But `z*G = (-a)*G` (DL = -a). The discrete logs differ by 1:
- `C_precomp` has DL = 1-a
- `z*G` has DL = -a

Therefore `C_precomp ≠ z*G`, producing:
```
L = s*G + c_p*P + c_c*C_precomp
  = aG + c*mu_C*( (1-a) - (-a) )*G
  = aG + c*mu_C*G          ← EXTRA TERM c*mu_C*G
```

The extra `c*mu_C*G` corrupts the challenge hash → `final_c ≠ sig.c1` → CLSAG fails.

### The Fix

File: `src/wallet/wallet2.cpp:10070`
```diff
- src.mask = td.is_rct() ? td.m_mask : rct::zero();
+ src.mask = td.is_rct() ? td.m_mask : rct::identity(); // scalar 1 matches zeroCommit's implicit blinding factor
```

With `src.mask = 1`:
```
z = inSk.mask - a_pseudo = 1 - a
C_precomp = (1-a)*G = z*G   ✓
L = aG - c*mu_P*p*G - c*mu_C*(1-a)*G + c*mu_P*p*G + c*mu_C*(1-a)*G = aG   ✓
```

**Same fix also corrects the MLSAG `proveRctMGSimple` path.**

# LESSONS LEARNED
===========================================================================

1. **The CLSAG code was correct** — the signer and verifier both implement the same
   algorithm. The bug was in the DATA fed into the signing path.

2. **`zeroCommit` is a landmine for non-RCT** — it returns `1*G + amount*H`, not
   `0*G + amount*H`. The implicit scalar 1 must be matched everywhere.

3. **Monero inherited this same bug** — but never triggered because non-RCT outputs
   were migrated to RingCT (receiving proper masks) before CLSAG activation. The MLSAG
   migration path would also have failed with this bug, but plausibly the monero migration
   happened in a way that avoided it or there's a subtle compensating factor elsewhere.

4. **Debug logging saved days** — being able to compare every intermediate value
   between wallet and daemon pinpointed the exact discrepancy (L vs aG). Without it,
   this would have been a blind guessing game.
